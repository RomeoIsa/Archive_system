# Project code explanation (excluding checklist.md and uploads/*)

This file explains each source file’s code blocks, what each block does, and what it interacts with in other files.

> Scope notes:
> - Excludes: `public/checklist.md` and everything under `uploads/`.
> - Includes: PHP/HTML/CSS assets present in the repo.
> - When a file calls another PHP page via `include`/links/forms/fetch, that interaction is documented.

## 1) `config/db.php`

### Code
```php
<?php
$conn = new mysqli("localhost", "root", "", "archive_system");

if ($conn->connect_error) {
    die("Connection failed: " . $conn->connect_error);
}
?>
```

### What it does
- Creates a global MySQL connection object `$conn` using `mysqli`.
- Immediately terminates the request if the DB connection fails.

### Interactions
- Every PHP page that `require "../config/db.php";` (or similar) depends on `$conn` to run SQL.

## 2) `includes/access.php`

### Code
```php
<?php

function canViewFile($file, $session_user_id, $session_institution_id) {

    if ($file['user_id'] == $session_user_id) {
        return true;
    }

    if ($file['visibility'] === 'public') {
        return true;
    }

  
    if (
        $file['visibility'] === 'institution' &&
        $file['institution_id'] == $session_institution_id
    ) {
        return true;
    }


    return false;
}
```

### What it does
- Defines `canViewFile(...)` which decides whether the session user can view a given `$file` record.
- Rules:
  1. Owner can view (`file.user_id == session_user_id`).
  2. Public files can view.
  3. Institution files can view if `file.institution_id == session_institution_id`.
  4. Otherwise deny.

### Interactions
- Intended to be used by file-viewing endpoints (e.g., could be used in `public/view_file.php`).
- In the current codebase snapshot, `public/view_file.php` implements its own access logic and does **not** call `canViewFile`.

## 7) `public/view_file.php`

### Bootstrap + auth
- Requires login; loads `$conn`.

### Fetch by ID
```php
$file_id = intval($_GET['id']);
$stmt = $conn->prepare("SELECT * FROM uploads WHERE id = ?");
$stmt->bind_param("i", $file_id);
```
- Fetches file metadata.

### Access control block
```php
function canAccessFile($file, $user_id, $institution_id) {
    if ($file['visibility'] === 'private') return $user_id && $file['user_id'] == $user_id;
    if ($file['visibility'] === 'institution') return $institution_id && $file['institution_id'] == $institution_id;
    if ($file['visibility'] === 'public') return true;
    return false;
}
```
- Grants/denies based on visibility and `institution_id` in session.

### Recent view tracking block
```php
SELECT id FROM recent_views WHERE user_id = ? AND upload_id = ?
```
- If exists: updates `viewed_at = NOW()`.
- Else: inserts into `recent_views`.

### Preview rendering
- Builds `$filePath = "../uploads/" . $file['file_name'];`
- If `file_type` is image or txt-like: shows `<img>`.
- If `pdf`: shows `<iframe>`.
- Else: shows a “Preview not available” message and renders a download link.

### Interactions
- Includes logic that conceptually overlaps with `includes/access.php` but does not call it.
- Writes to DB table `recent_views`.
- Provides download route to `download.php?id=...`.

## 8) `public/download.php`

### Auth + fetch file
```php
$stmt = $conn->prepare("SELECT * FROM uploads WHERE id = ?");
```

### Access control block
- Implements its own `$allowed` logic:
  - owner OR visibility public OR visibility institution with matching institution.

### Logs downloads
```php
INSERT INTO downloads (user_id, upload_id, institution_id) VALUES (?, ?, ?)
```
- Records download events.

### File transfer block
- Builds `$filePath = "../uploads/" . $file['file_name'];`
- Checks file exists.
- Sets headers:
  - `Content-Type: application/octet-stream`
  - `Content-Disposition: attachment; filename=...`
- Uses `readfile($filePath)` then `exit()`.

### Interactions
- Depends on `uploads` table and `downloads` table.
- Serves physical files from `../uploads/`.

## 12) `public/upload_handler.php`

### Auth
- Requires login and loads `$conn`.

### Input extraction
- Reads title, description, visibility from `$_POST`.
- Reads uploaded file from `$_FILES['file']`.

### Validation block
- Rejects if `$fileError !== 0`.

- Creates unique name:

- Moves uploaded temporary file to `../uploads/$newFileName`.

(user_id, title, description, file_name, file_type, file_size, visibility, institution_id)
VALUES (?, ?, ?, ?, ?, ?, ?, ?)

- Sets session `upload_success` or `upload_error`.
- Redirects to `dashboard.php`.

### Interactions
- Called by `public/dashboard.php` upload modal form.
- Creates physical file in `../uploads/`.
- Inserts into DB table `uploads`.

## 13) `public/library.php`

### Auth + theme
- Requires login.
- Sets `$activePage = 'library'` for sidebar.

### Filters
- Reads `search`, `type`, `sort` from `$_GET`.

### Main query
```sql
SELECT uploads.*, users.name AS uploader_name, saved.upload_id AS saved_upload_id
FROM uploads
JOIN users ON uploads.user_id = users.id
LEFT JOIN saved ON uploads.id = saved.upload_id AND saved.user_id = ?
WHERE (uploads.visibility = 'public'
       OR (uploads.visibility = 'institution' AND uploads.institution_id = ?))
  AND (uploads.title LIKE ? OR uploads.description LIKE ?)
```
- Shows only public + institution-matching uploads.
- Uses LEFT JOIN `saved` so UI can display save state.

### Sort
- `ORDER BY uploads.created_at DESC` (latest) or ASC (oldest).

### Render save/un-save buttons
- Uses HTML button with class `save-btn`.
- JS calls `fetch('toggle_save.php', { method:'POST', body:'upload_id=...' })`.

### Interactions
- Includes `../includes/sidebar.php`.
- Uses `toggle_save.php` for favorites.
- Provides routes to:
  - `view_file.php`, `download.php`
